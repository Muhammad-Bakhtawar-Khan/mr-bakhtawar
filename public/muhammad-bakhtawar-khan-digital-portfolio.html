Personal perspective, learning and working principles
A PERSONAL PERSPECTIVE

My work begins with curiosity: how does this system work, who is it for, and what would make it more useful?

01 / BACKGROUND

A growing practice.
An independent point of view.

I’m a technology enthusiast and digital creator building my skills across web development, modern JavaScript, React, applications, APIs and automation. I enjoy the point where technical problem-solving meets creative thinking: turning a complicated task into something understandable, usable and considered.

This portfolio brings together my independent projects, experiments and professional interests. Some ideas become useful browser tools; others become a way to understand a new integration, a design decision or the behavior of an application. I want the work to communicate what I am learning—not suggest that the learning is finished.

MBK is my professional identity. MBK Global is the associated brand connecting these projects and my longer-term direction. The person behind both is Bakhtawar Khan.

02 / TECHNICAL INTERESTS

Different disciplines.
The same curiosity.

Web experiences

HTML, CSS, JavaScript and React provide a foundation for exploring responsive interfaces, reusable components, accessible navigation and clear application states. I care about how a product feels to use as well as how it is put together.

Connected systems

APIs interest me because they make separate tools work together. I’m learning through request handling, data transformation, integration experiments and understanding what happens when a service is slow, unavailable or returns unexpected data.

AI & useful automation

My interests include knowledge-based assistants, chatbots, WhatsApp workflows and practical AI-powered tools. The useful question is not whether a task can be automated, but which parts should be—and where a person should remain in control.

Beneath the interface

Reverse engineering, code analysis, technical research and web security help me investigate software behavior. My approach is permission-based and defensive: understand the system, respect its boundaries and protect other people’s information.

Discoverability & quality

Technical SEO, metadata, crawlability, page performance and thoughtful content structure connect development with the people who need the result. Good presentation should support useful information, not replace it.

03 / LEARNING IN PRACTICE

A more honest way to describe the toolkit.

Visible in this portfolio
HTML, CSS, JavaScript, React components, responsive layouts and structured technical content. The pages and linked projects are the places to review the work.
Developing through experiments
Python, API integration, AI-assisted applications, conversational interfaces, workflow automation, performance and technical SEO.
Exploring further
Backend development, API design, databases, application architecture, Android and mobile applications, Telegram bots, supported social integrations, deployment and cloud tools.

These distinctions matter. An interest is not a certification, and a prototype is not evidence of a production deployment. I prefer to explain a project’s actual scope and constraints rather than present every technology as an established specialization.

04 / MAKING & REFLECTING

Learning becomes clearer
when something has to work.

Personal projects give me room to test an idea from more than one angle. MBK TV explores media discovery; MBK Markets explores a market-data interface; MBK Video Downloader and Text to Handwriting explore practical web utilities; Noor-e-Quran brings a different set of content and usability questions.

Their value is not only in the visible result. Planning a flow, investigating a failure, checking a layout on a smaller screen and revisiting a confusing decision all develop a better understanding of the product. Features and availability can change; project pages provide the context rather than a promise of permanent functionality.

05 / WORKING PRINCIPLES

Clarity over complication.

I start by understanding the need, the audience and the constraints. Then I break the problem into manageable pieces, build a small version, inspect what happens and refine it. I value reliable behavior, clear communication and room for feedback more than adding features simply because they are possible.

Responsible technology is part of that process. Privacy, accessibility, respectful communication and permission-based research should shape the work from the beginning. Collecting less data, explaining limitations and making an interface usable for more people are practical development decisions—not finishing touches.

06 / LOOKING AHEAD

Deeper understanding.
More useful things.

I want to strengthen my development skills, understand application architecture more deeply and connect AI, APIs and automation in ways that solve real problems. My direction includes useful tools, chatbots and digital products with clear purposes and understandable boundaries.

My journey is still evolving. The aim is a stronger body of work and a professional identity grounded in thoughtful execution, not the size of the claims. If you have a project that fits that approach, I’d welcome a clear conversation about what you want to build.
