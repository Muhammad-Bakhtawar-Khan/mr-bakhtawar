Deploying and Maintaining a Static Website

A reliable deployment process makes the published output predictable and gives you a way to detect regressions before and after release.

Confirm the publish directory

Identify which directory the host actually publishes and keep hosting configuration files such as Netlify _headers and _redirects in the appropriate publish root. Do not assume a configuration file for another provider controls the live deployment.

Keep redirects direct

Use permanent redirects only when a URL has a close, useful replacement. Avoid loops, chains and redirecting unrelated pages to the homepage. Update internal links and sitemap entries to point directly to final canonical URLs.

Set sensible response headers

Use HTTPS, nosniff, a restrictive referrer policy and framing protection appropriate to the site. Begin Content Security Policy in report-only mode when existing inline code or third-party resources may be affected. Review reports before enforcement.

Use a repeatable test checklist

Check HTML structure, internal links, metadata, canonical URLs, sitemap coverage, structured data, image references, keyboard navigation and responsive layouts. Record the command and result for each test rather than marking unrun checks as passed.

Deploy with a rollback path

Keep an untouched source backup and a separate implementation copy. Review the diff, publish only after owner review, then test live status codes, redirects and headers. Keep Search Console and real-user performance monitoring as post-deployment tasks.

About this guide: This is general educational guidance. Adapt recommendations to your site's actual stack, risk and audience, and verify changes before publishing.
